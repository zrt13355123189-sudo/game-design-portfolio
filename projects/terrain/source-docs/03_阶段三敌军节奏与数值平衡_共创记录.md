# 阶段三：敌军节奏、Boss 房与数值平衡 - 共创计划与记录

最后更新：2026-09-01
文档性质：策划主导的共创记录；阶段三的当期工作锚点

## 1. 文档定位

本文件服务于“面粉关”单关 Demo 的阶段三：敌军节奏、Boss 房与数值平衡。

阶段三不采用固定的程序任务清单。策划应以实际局面、实机游玩与可解释的战术阈值为中心，持续记录：

- 已确认的敌军职责、站位、数值、武器、技能、掉落、激活条件与资源量。
- 正在验证的假设、局面样本、玩家路线、失败原因与后续调整方向。
- 只有确认为通用系统缺陷或阻塞性 Bug 的问题，才转化为代码任务；其它问题优先由关卡配置、数值或信息呈现解决。

本文件不替代以下权威来源：

- `Docs/面粉关关卡策划案.md`：关卡的整体设计意图与机制思路。
- `Docs/Demo实施阶段计划/总计划与验收矩阵/“面粉关”单关 Demo 实施总目标计划.md`：Demo 的总目标与阶段门槛。
- `DesignTables/Units.xlsx`、`DesignTables/Items.xlsx`、`DesignTables/skill.xlsx`：可导入的正式数据来源。

发生冲突时，优先级为：已确认的策划结论 > 总目标计划 > 本记录 > 旧的历史说明。

## 2. 阶段三工作方式

每一轮以如下循环推进：

```text
策划提出局面与预期博弈
    -> 数值模型/阈值推演
    -> Tiled 与配置表调整
    -> Godot 实机完整游玩
    -> 记录路线、回合数、资源、减员、异常与结论
    -> 下一轮假设
```

每次实机验证建议至少记录：选择的出战角色与流派、路线、总回合数、关键击杀/被击杀阈值、钥匙与面粉使用、敌方烹饪推进、Boss 房处理方法，以及任何 AI 或信息显示问题。

高台验证仍遵循总目标计划中的前置原则：关注高度如何改变击杀线、威胁范围、安全格与未来行动窗口，而不是把建造本身视为额外的行动税。实验性局面优先在 `high_ground_lab` 中验证，再决定是否迁移至面粉关。

## 3. 当前已确认边界

- 普通敌军当前以 28 级为默认基线；精英与 Boss 的等级、属性修正、技能和装备由后续关卡设计单独填写。
- 敌军默认是白板档案：职业模板不自动附带流派技能。技能、道具、掉落和特殊 AI 均可按关卡实例单独覆盖。
- 本阶段重点是完整关卡的节奏与可玩性，不提前冻结最终敌方技能组合、掉落、面粉资源总量或路线强度。
- 移动力不是随机成长。它按每升一级累积固定成长点、满 100 点增加 1 点移动力；运行时等价公式为 `基础移动力 + floor((等级 - 1) x 移动力成长 / 100)`。

## 4. 时间线记录

### 2026-09-09 - 敌方空间责任算分试点终止并完整回退

**结论**

- 责任势能、定点无反击火力、下一回合威胁、攻击收益、反击风险与破阵收益共同参与的综合空间算分，在面粉关 A/B 线实机测试中未形成可读、稳定且容易归因的敌军行为。
- 典型结果包括敌军抵达责任点后缺乏进攻性、同组单位在相近局面下表现分裂，以及单一异常可能同时受到候选生成、路径、责任曲线和多项权重影响。继续调参的成本已经妨碍关卡配置与节奏验证。
- 本轮完整回退该试点：恢复升级前的通用敌人攻击、接近与寻路逻辑；删除责任点运行时字段、Tiled 属性、marker、导入校验和专项测试，不在现行架构中保留停用分支。
- 这次结论不否定“限制无限拉怪”或“减少无反击阵地白嫖”本身的问题价值，但后续必须把它们拆成可独立观察的单一问题，以玩家能够从战场直接理解的简单规则分别验证。
- 阶段三重新以关卡设计推进为优先。任何新的通用 AI 试验都应先在最小局面中建立明确的成功/失败标准，避免再次以综合评分替代可解释的战棋规则。

**归档**

- 完整数学模型、调参过程与失败复盘移至 `Docs/策划废案/敌人AI高台博弈空间决策升级方案.md`，仅作为历史样本，不再构成开发计划或策划执行依据。

### 2026-09-04 - 树林简化为基础回避地形，减嘲讽机制后置

**结论**

- 树林改为站在其上的单位获得 `回避 +20`；敌我双方均适用。
- 该调整服务于面粉关 Demo 的初见可读性：树林作为最熟悉的基础地形，应让玩家立即理解其保护价值，而不要求其先掌握复杂的索敌优先级关系。
- 旧减嘲讽算法保留，不再由树林调用。后续将把它投放为我方专属奖励地形，作为玩家在理解攻击范围与诱导后使用的高级工具；该奖励地形不再具有“敌人站在同类地形也会优先索敌”的对称规则。
- 后续关卡设计可继续用树林的回避窗口支持推进、拉扯和风险控制；不要再把树林视为敌方索敌操控工具。

### 2026-09-02 - 高台实验场警戒组与移动威胁验证

**结论**

- 高台实验场内所有当前配置的敌军均使用 `guard_until_triggered`，并归入 `high_ground_lab_alert` 警戒组。
- 警戒单位默认不移动；任一成员的合法“移动后攻击范围”发现对立阵营单位时，同组仍处于警戒状态的成员一起不可逆地激活为普通索敌 AI。
- 警戒单位尚未激活时，危险范围也必须按其移动后攻击可及范围显示；这与真正固定不动的 `stationary` / `scripted` 敌军区分开。
- 该逻辑属于通用 AI 规则，可供后续关卡通过 `ai_profile_id` 和 `ai_group_id` 直接复用；面粉关 Boss 房和厨房脚本单位继续保持各自的固定/脚本例外。

### 2026-09-02 - 警戒组回合前激活与显式行动顺序

**结论**

- Tiled 敌军对象使用单一 `action_order` 整数。数值越小，通用敌方行动越靠前；正式关卡采用“前两位为 AI 组优先级、后三位为组内顺序”的分段编号，例如 `10001`、`10002`、`20001`。未填写保持既有 Tiled 对象创建顺序，同值按 `spawn_id` 稳定决胜。`ai_group_id` 只负责共同警戒激活；Boss 房角楼、厨房教学、厨师等已由关卡脚本接管的特殊单位保持脚本优先，不受通用编号干扰。
- 警戒组在敌方回合开始、逐个执行敌军前完成联合判定。任意成员的移动后攻击范围触及对立单位时，整组本回合同步激活；因此后序成员触发时，前序成员也不会白白待机。
- 高台实验场以巫师 `1`、将军 `2` 验证该顺序：仅将军能发现玩家时，巫师仍会在同一敌方回合进入正常索敌。
- 面粉关 Boss 房等由关卡脚本明确编排的联动顺序继续优先于通用排序，避免破坏可解释的角楼辅助敌 -> 炮台行动链。

### 2026-09-01 - 正式职业基础敌军数据接入

**结论**

- 敌方正式基础单位改为职业模板：狂战士、勇者、将军、斥候、狙击手、巫师、修女、建筑师；狂战士采用“钻研”对应的职业基础值与总成长率。应援狂战士属于后续独立角色设计，不作为通用敌方狂战士基线。
- `enemy_spear` 保留为长枪兵兼容模板，供现有长枪兵与 Boss 历史档案继续引用；它不冒充正式职业基础数值表中的职业。
- 所有正式职业成长字段以百分比记录。等级属性统一为 `基础属性 + floor((等级 - 1) x 成长率 / 100) + 档案修正`；这同时正确表达了移动力的固定累计规则，不引入随机成长。
- 普通敌方档案新增 28 级白板基线；每种职业默认装备对应的铁质/基础武器。Boss、厨房厨师、教学友军与教学巫师继续使用独立档案和必要的关卡修正。
- 当前面粉关的敌方技能、掉落、精英数值和具体站位职责尚未冻结，后续由 Tiled 实例覆盖与关卡配置继续设计。

**已验证结果**

- 28 级巫师：HP 26、力 0、魔 29、技 14、速 22、幸 17、守 10、魔防 18、移动 6。
- 28 级建筑师：HP 33、力 22、魔 14、技 27、速 17、幸 13、守 23、魔防 21、移动 6。
- 斥候移动力成长阈值：13 级仍为 6 移动，14 级累计越过 100 后为 7 移动。

**后续观察点**

- 在高台实验场与面粉关中逐步验证各职业 28 级基础档案的击杀线、追击线、反击风险和武器克制表现。
- 当敌人职责、技能、掉落与站位共同确定后，再将对应实例配置写入 Tiled；不为尚未设计好的敌人类型提前建立大量僵化档案。

# 面粉关 Demo 体验基线与流程设计

最后更新：2026-08-11  
对应总目标阶段：阶段 0 - 制作基线与范围冻结  
文档性质：关卡体验与流程权威说明

## 1. 文档目的

本文档定义“面粉关”单关 Demo 的目标玩家体验、完整流程、失败规则、教学策略与信息公开原则。

它不记录敌人精确数值、Tiled 坐标、脚本实现或美术制作方法。数值和对象配置应在对应的关卡数据、策划案或阶段执行计划中维护。

## 2. 体验定位

- 目标受众：喜欢中高难度战棋、愿意推演敌我数值与行动顺序的玩家。
- 难度定位：按正式游戏的最高难度思路设计，但规则必须透明、可计算、可复盘。
- 熟练通关时间：约 60 分钟。
- 初见通关时间：允许显著长于 60 分钟；玩家需要阅读信息、理解高台、观察厨房机制并处理局部战棋博弈。
- 容错方向：允许减员与局部失误；不要求一次无失误通过。Boss 房和城堡直推路线应存在明显风险，但不能依赖未知规则制造必然失败。

本关的难点来自战术判断、资源取舍和空间控制，不来自隐藏触发、错误范围提示或难以理解的操作限制。

## 3. 完整游玩流程

```text
标题页
  -> 关卡简报 / 开局教学
  -> 战前准备
  -> 战前部署与有限地形配置
  -> 面粉关战斗
      -> 野外推进
      -> 厨房资源争夺（可选）
      -> 城堡推进
      -> Boss 房解法选择
  -> 胜利或失败结果页
  -> 重开本关 / 返回标题页
```

### 3.1 标题页

标题页的正式功能限定为：

- 开始面粉关。
- 读取关卡存档。
- 制作人员 / 操作说明。
- 退出游戏。

标题页不承担主线章节选择、家园、角色养成或长期存档管理。

### 3.2 关卡简报与开局教学

- 不接入正式主线剧情、主角剧情或长对白。
- 简报只提供本次作战目标与必要的关卡语境。
- 开局弹出一次可关闭的教学说明，介绍烹饪与敌我共享的烹饪增益机制。
- 开局教学内容同步写入情报书，便于之后复查。
- 面粉爆炸不在开局全部讲透，而是在局内事件中教学。

### 3.3 战前准备

玩家可完成：

- 从已配置角色中选择本关的七名出战角色。
- 保留两名替换预留角色。
- 对允许切换的角色选择流派。
- 在预设部署点间换位。
- 使用有限额度完成允许的地形配置。

战前配置的目标是让玩家在进入关卡前形成初步策略，而不是将最佳解预先固定。厨房、城堡、高台与 Boss 房仍应在局内产生足够的临场决策。

### 3.4 战斗中的三段结构

#### 野外

- 用于建立地图尺度、角色操作和路线选择。
- 提供通往厨房与城堡的初始分流。
- 不应在玩家尚未理解基础操作前施加 Boss 房级别的压力。

#### 厨房

- 厨房是可选但强力的支路，不是通关硬门槛。
- 面粉可以用于烹饪，也可以用于撒粉并在封闭空间引爆；两种用途互斥。
- 敌方厨师会推进烹饪增益，形成随时间提高的软狂暴压力。
- 忽略厨房仍应可以击败 Boss，但敌方增益会改变追击、击杀和生存阈值，使城堡推进显著更危险。

#### 城堡与 Boss 房

- 城堡是传统战棋推进的主体区域。
- Boss 房用于集中展示警戒攻击、角落炮台高台联动、精确射程环与危险范围判断。
- 直接推进可以成立，但应有较高减员风险。
- 玩家可通过拆角、诱导、地形构筑、厨房资源、粉尘爆炸和远程射程控制寻找不同突破方式。

## 4. 胜败、减员与存档

### 4.1 胜败规则

- 击败 Boss 即取得胜利，不要求消灭全体敌军或完成烹饪。
- 我方所有可操作单位退场时判定失败。
- 单位 HP 归零后仅在本局退场，不可在本局复活。
- 本 Demo 不做跨关永久死亡、长期资源损失或剧情惩罚。

### 4.2 局内存档

- 仅在我方回合、未打开行动菜单或目标选择时允许存档。
- 存档完整保存当前局面；读取后继续当前回合。
- 提供 3 个可覆盖的独立局内存档槽。
- 读取存档不会删除原存档，优先服务高难度推演与试玩体验。
- 失败结果页提供快速重开本关与返回标题页。

## 5. 教学与情报书

### 5.1 教学原则

- 关键规则必须可见、可查、可推断。
- 教学事件可以暂时冻结地图输入，确保玩家看见关键演出；事件结束后不强迫玩家执行指定动作或走指定路线。
- 高难度来自决策，不来自把致命规则藏在看不到的位置。

### 5.2 烹饪教学

- 在关卡开始时进行一次可关闭说明。
- 说明烹饪消耗面粉、敌我共享增益表、增益按顺序循环推进。
- 信息写入情报书。

### 5.3 粉尘爆炸教学

- 首次由友军教学单位进入厨房触发事件。
- 厨师的反应、粉尘、热源与封闭空间爆炸以关卡内演出展示。
- 事件后由我方进行简短的教学性对话，并向情报书新增爆炸说明。
- 教学单位和事件只服务于规则理解，不承担正式剧情系统。

### 5.4 Boss 房高台教学

- Boss 的“警戒攻击”必须可从选中 Boss 后的技能说明中读取。
- 角落炮台的潜在危险范围必须始终正确显示。
- 玩家进入大城堡警戒区后的下一回合开始，由建筑师台词提示 Boss 房守军会调整高台射程。
- 对应说明写入情报书。

## 6. 信息公开原则

- 敌方移动范围、攻击范围、炮台可能调整后的潜在攻击范围必须与实际规则一致。
- UI 要显示行动结果的重要来源：武器、地形、高台、技能、Buff、物件和关卡机制。
- 任何会改变伤害、射程、行动限制、资源进度或胜败的机制，玩家都应能从单位详情、预测、地图标记或情报书中确认。
- 玩家可以不知道最优解，但不应因为错误、迟滞或不完整的信息显示而受罚。

## 7. 输入与平台边界

- 正式支持鼠标与键盘。
- 鼠标负责选格、菜单点击和地图拖拽；键盘负责既有镜头、缩放、危险范围、全屏等快捷操作。
- 必要快捷键应在操作说明或对应界面中可查。
- 手柄导航和按键重映射是远期较高优先级项目，不进入本 Demo 范围。
- 运行基准为 Windows PC、1920x1080；窗口化与无边框全屏显示的信息量保持一致。

## 8. 非目标

- 不制作正式剧情、主角、主线章节、家园或长期养成。
- 不制作经验、升级、成长率、跨关资源与永久死亡循环。
- 不以强制路线、强制操作或连续长篇说明取代关卡教学。
